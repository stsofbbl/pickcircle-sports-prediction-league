# YOSO 夏の甲子園2026 総合テスト計画

更新日: 2026-07-22

## 1. 目的

4人がオンラインで参加し、フェーズ1から決勝後の最終ランキングまでを大会進行順に完走できることを確認する。画面表示だけでなく、Supabase保存、権限、再読込、得点内訳、再計算の冪等性を合格条件に含める。

## 2. 正常系の主シナリオ

固定テストデータとして4人、49校、48試合、固定オッズ、1回戦開始校34、2回戦開始校15を用意する。高校名はテスト用IDでよく、表示名による照合を禁止する。

| 手順 | 操作 | 主要な期待結果 |
| --- | --- | --- |
| 1 | 4アカウントで同じリーグへ参加 | 全員が別のplayer IDとして解決される |
| 2 | 管理者が大会、49校、組合せ、固定オッズ、各締切を登録 | 別端末で同じ大会が読める |
| 3 | 全員がフェーズ1の8校とキャプテンを保存 | 本人の予想だけが締切前に復元される |
| 4 | 管理者がフェーズ1を締切 | 以後の変更がサーバーで拒否される |
| 5 | Best 16まで結果を順番に保存 | 2回戦開始校の初戦敗退は0、1回戦勝利後の2回戦敗退は1になる |
| 6 | Best 16を確定して後半準備をプレビュー | 暫定得点、同点抽選、ドラフト順、リベンジ資格が表示される |
| 7 | 管理者がリベンジとフェーズ2を開く | 対象者だけリベンジ選択可、ドラフトは固定順で開始する |
| 8 | 16回の正式ドラフトを完了 | 16校が重複なく4校ずつ割り当てられる |
| 9 | 対象者がリベンジ校を確定 | 別端末で同じ選択が復元される |
| 10 | Best 8、Best 4まで結果を保存 | フェーズ1、リベンジ、フェーズ2基礎点が再計算される |
| 11 | Best 4を確定してゾンビを開く | フェーズ2全滅者だけが他人所有のBest 4校を選べる |
| 12 | ゾンビ対象者が準決勝敗退校を予想 | 締切前は編集可、締切後は拒否される |
| 13 | 準決勝結果を保存 | 1人的中対象は40→20、2人以上的中対象は40→0になる |
| 14 | 決勝カード確定後にフェーズ3を開く | 決勝2校が固定表示され、得点だけ入力できる |
| 15 | 4人が異なる決勝スコアを保存 | 同点予想は拒否され、別端末で復元される |
| 16 | 決勝結果を保存 | 完全一致50、または完全一致なしの最接近30が反映される |
| 17 | 最終ランキングを表示 | 全フェーズ内訳の合計と順位が一致する |
| 18 | 全アカウントで再ログイン・再読込 | 予想、資格、得点、順位が同一である |
| 19 | 同じ決勝結果を再保存 | 得点が増えず、順位も変わらない |

## 3. 必須テストデータ条件

- 少なくとも1人はBest 16時点でフェーズ1の8校が全滅する。
- その人について、直接倒した高校がBest 16に残るケースを作る。
- 別ケースとして、直接倒した高校が1校もBest 16に残らないフォールバックを作る。
- フェーズ1暫定得点の同点者を2人作り、抽選結果が再読込後も変わらないことを確認する。
- Best 4時点でフェーズ2の4校が全滅する人を最低1人作る。
- 1人的中と2人以上同一校的中は別シナリオで確認する。
- フェーズ1とフェーズ2で同じ高校を保有する人を作り、両方が得点されることを確認する。
- フェーズ3は完全一致あり、完全一致なし、最接近完全同条件の3ケースを用意する。

## 5. 得点検算

テスト用オッズを全校4.00、平方根倍率2.00にすると手計算しやすい。

- 通常のBest 8: `2 × 2 = 4`
- キャプテンのBest 8: `2 × 2 × 1.2 = 4.8`
- リベンジBest 8: `(2 - 1.5) × 2 = 1`
- リベンジ優勝: `(5 - 1.5) × 2 = 7`
- フェーズ2準決勝敗退: 40
- ゾンビ1人的中後: 20（調整 -20）
- ゾンビ2人以上的中後: 0（調整 -40）
- フェーズ3完全一致: 50
- 完全一致なしの最接近: 30

## 6. 合格条件

- 正常系19手順を4アカウント・2端末相当で完走できる。
- E01〜E22が期待どおりになる。
- 得点内訳の合計とランキング合計が一致する。
- 同じ入力から何度再計算しても同じ結果になる。
- 締切、資格、所有者、本人性をブラウザのローカル値だけで突破できない。
- 本番Supabaseへの書込みやmigration適用は、別途明示承認を得るまで行わない。
