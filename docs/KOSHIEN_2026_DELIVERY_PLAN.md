# 夏の甲子園2026 リリース計画

最終更新: 2026-06-26

## 目標

夏の甲子園までに、仲間内で実際に使えるYOSOアプリにする。

W杯2026のUIはプロトタイプとして残し、当面は深追いしない。開発の主戦場を以下へ移す。

- Supabase Auth
- Supabase Postgres
- 夏の甲子園向けプリセット
- スマホで迷わず使える予想、結果入力、ランキング

## 現在の前提

- GitHub Pagesの静的フロントエンドを継続する。
- 共有データ置き場はGoogle SheetsではなくSupabase Postgresへ切り替える。
- ブラウザにはSupabase Project URLとanon public keyだけを置く。
- `service_role` keyやsecret keyはフロント、GitHub、チャットへ入れない。
- Supabase未設定時は既存localStorageで動くフォールバックを残す。
- Google Sheets連携UIは保留扱いで残すが、甲子園MVPの主経路にはしない。

## 実装済み

- Supabase schema / RLS SQL
- Supabase Authの新規登録、ログイン、ログアウト、セッション維持
- Confirm Email ON前提の確認メール導線

- `PASSWORD_RECOVERY` 検出後の新パスワード更新UI
- `profiles.display_name` 保存
- 甲子園イベント、自分の予想、結果のSupabase保存土台

## 直近の完成条件

まずは甲子園GUIの大幅変更に入らず、次を完成条件にする。

- 端末Aで管理者が甲子園大会、出場校、結果を保存できる
- 端末Aで参加者が自分の甲子園予想を保存できる
- 端末Bで同じユーザーまたは同じリーグ参加者がログインできる
- 端末BでSupabaseから甲子園大会、出場校、自分の予想、結果を読み込める
- 締切前は自分の予想だけ見える
- 締切後は同じリーグの他メンバー予想も見える

## 甲子園プリセット方針

2026年8月版は固定トーナメント表ではなく、以下の方式を採用する。

- 49代表校から8校を選ぶ
- 8校のうち1校をキャプテン校にする
- キャプテン校は得点2倍
- 決勝戦の合計得点予想を同点決着用に持つ
- 友達同士で同じ学校を選べる
- 管理者が各校の勝ち上がり結果を入力する

得点:

| 到達段階 | 加算pt |
| --- | ---: |
| 32強 | 1 |
| 16強 | 2 |
| 8強 | 4 |
| 4強 | 8 |
| 決勝 | 16 |
| 優勝 | 32 |

ポイントは累積する。優勝校を通常指名していれば63pt、キャプテン校なら126pt。

## 手動E2Eテスト

### 事前準備

1. Supabase SQL Editorで `supabase/schema.sql` と `supabase/rls-policies.sql` を実行済みにする。
2. Authentication > Providers でEmail providerを有効にする。
3. Confirm EmailはONのままにする。
4. Authentication > URL Configurationに `docs/SUPABASE_SETUP.md` のRedirect URLを入れる。
5. ローカルまたは公開URLで `supabase-config.js` を読み込める状態にする。
6. `auth.enabled: true` と `sync.autoSaveKoshien: true` を設定する。

### 管理者ユーザー

1. 管理者用メールアドレスで新規登録する。
2. 確認メールを開いてログインする。
3. 夏の甲子園大会を作成または選択する。
4. 代表校リストを編集する。
5. 自分の8校ピック、キャプテン校、決勝合計得点を入力する。
6. Supabaseへ保存されたことを確認する。
7. 別端末または別ブラウザで同じ管理者としてログインし、甲子園大会、代表校、自分の予想が読み込まれることを確認する。

### 一般メンバー

1. 一般メンバー用メールアドレスで新規登録する。
2. 確認メールを開いてログインする。
3. 同じリーグに参加できることを確認する。
4. 管理者が作成した甲子園大会と代表校が読み込まれることを確認する。
5. 自分の8校ピック、キャプテン校、決勝合計得点を入力する。
6. 別端末または別ブラウザで同じメンバーとしてログインし、自分の予想が読み込まれることを確認する。
7. 締切前に他メンバーの予想が見えないことを確認する。
8. 管理者が締切後状態へ変更した後、同じリーグの他メンバー予想が見えることを確認する。
9. 一般メンバーが大会、出場校、結果を変更できないことを確認する。
