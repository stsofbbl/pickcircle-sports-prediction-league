# #61 甲子園HTTP競合修正候補（未承認・未適用）

PR #60 の実HTTP検証で 40001 を明示した業務競合がタイムアウトし、PT409 で直ちに409を返すことを確認済み。甲子園本番RPC5件について、実カタログの関数定義から決定的競合コードだけを変更する候補。得点・状態・入力条件・その他のエラーは変更しない。

- apply.sql は関数ごとの既存/変更後のbody hash、所有者、ACL、SECURITY DEFINER、search_path、anon実行不可を検査し、5関数を1 DO文で変更する。既存定義と異なる場合は全体停止。実際のserialization failureは対象外。
- rollback.sql は逆向きの厳密なhash検査。関数の他メタデータの変更も拒否。
- 試験は実関数定義と合成した最小schemaを使用。5つの実競合分岐の変更前後とrollbackを検証。正常保存・確定分岐や本番全schemaの代替ではない。
- フェーズ2の既存状態再取得は旧40001とPT409両方に対応。その他のエラー経路は既存の動作を維持。
- #58の未適用draft-open候補は別途検討し、release manifestを壊さない。既存本番RPCの障害実績は未確認。
- 本番適用はバックアップ・完全schemaでの検証・明示承認後。正式migrationではない。Vercelはこのbranchを無効化。

実HTTP試験: 前後・rollback SQL試験に加え、同じ実関数を使い捨てDBだけに適用し、固定バージョンPostgRESTから5つのstaleリクエストが即時HTTP 409/PT409、別会員・匿名・署名不正JWTが拒否されることを確認。合成DBのデータ指紋を前後比較する。JWTはCIのランダム鍵で署名した合成トークン。本番Auth・メール・ブラウザ・正常保存全経路の試験ではない。
